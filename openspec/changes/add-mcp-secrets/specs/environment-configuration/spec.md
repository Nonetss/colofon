## MODIFIED Requirements

### Requirement: Validated server environment

`@nonete/env/server` SHALL validate the server variables with t3-env and zod and export them as a typed `env` object:
- required: `DATABASE_URL`, `BETTER_AUTH_SECRET` (at least 32 characters), `BETTER_AUTH_URL` (URL) and `CORS_ORIGIN` (URL);
- with defaults: `NODE_ENV` (`development` | `production` | `test`, default `development`), `LOG_LEVEL` (`fatal` | `error` | `warn` | `info` | `debug` | `trace`, default `info`);
- optional: `ADMIN_EMAIL`, `ADMIN_PASSWORD` (at least 8 characters), `ADMIN_NAME`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_DISCOVERY_URL` and `SECRETS_ENCRYPTION_KEY` (the Base64 of exactly 32 bytes; it turns the user secrets on).

The content repositories are not configured through the environment: `CONTENT_DIR`, `CONTENT_REPO` and `CONTENT_REF` SHALL NOT be declared or read. Empty strings SHALL be treated as unset. Validation SHALL be skipped when `SKIP_ENV_VALIDATION` is set. `@nonete/env/web` SHALL validate the client variable `PUBLIC_SERVER_URL`.

#### Scenario: Missing required variable

- **WHEN** the backend starts without `BETTER_AUTH_SECRET` and without `SKIP_ENV_VALIDATION`
- **THEN** environment validation SHALL fail and the backend SHALL NOT start

#### Scenario: Defaults apply

- **WHEN** neither `NODE_ENV` nor `LOG_LEVEL` is set
- **THEN** `env.NODE_ENV` SHALL be `development` and `env.LOG_LEVEL` SHALL be `info`

#### Scenario: Malformed secrets key

- **WHEN** the backend starts with `SECRETS_ENCRYPTION_KEY` set to a value that is not the Base64 of 32 bytes
- **THEN** environment validation SHALL fail and the backend SHALL NOT start

#### Scenario: Retired content variables

- **WHEN** the repo (excluding archived OpenSpec changes) is searched for `CONTENT_DIR`, `CONTENT_REPO` and `CONTENT_REF`
- **THEN** no env schema, `.env.example`, compose file, script or current document SHALL reference them

#### Scenario: Two content sources

- **WHEN** the backend starts with the retired `CONTENT_DIR` and `CONTENT_REPO` both still set
- **THEN** environment validation SHALL NOT fail on them and the backend SHALL start, reading no content from them

#### Scenario: Build without secrets

- **WHEN** a production image is built with `SKIP_ENV_VALIDATION=1` and no runtime variables
- **THEN** the build SHALL NOT fail on environment validation

### Requirement: Scripts generate the unified file

`scripts/setup-dev.sh` SHALL write only the root `.env`, copying `.env.example` and replacing its placeholder secrets with values generated by `openssl` (`BETTER_AUTH_SECRET` and `SECRETS_ENCRYPTION_KEY`) and enabling the admin seed (`ADMIN_EMAIL`, `ADMIN_NAME`, a generated `ADMIN_PASSWORD`). It SHALL preserve an existing `.env` unless run with `--force`, SHALL create the file with mode `600`, and SHALL warn (never delete) about leftover `apps/*/.env` files that are no longer read. `scripts/bootstrap.sh` SHALL write a root `.env` using only the unified names, with a generated `SECRETS_ENCRYPTION_KEY`.

#### Scenario: Dev setup

- **WHEN** `scripts/setup-dev.sh` runs on a fresh checkout
- **THEN** it SHALL create the root `.env` with generated secrets, `SECRETS_ENCRYPTION_KEY` among them, and SHALL NOT create any `apps/*/.env`

#### Scenario: Existing file preserved

- **WHEN** `scripts/setup-dev.sh` runs and a root `.env` already exists, without `--force`
- **THEN** the existing file SHALL be left unchanged

#### Scenario: Stale per-app files

- **WHEN** `scripts/setup-dev.sh` runs and `apps/backend/.env` exists
- **THEN** it SHALL print a warning naming that file and SHALL NOT delete it

#### Scenario: Production bootstrap

- **WHEN** `scripts/bootstrap.sh` generates a deployment `.env`
- **THEN** the public URL SHALL be written as `CORS_ORIGIN`, `SECRETS_ENCRYPTION_KEY` SHALL hold the Base64 of 32 random bytes, and no retired name SHALL appear in it
