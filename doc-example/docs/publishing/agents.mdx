## El Markdown de cada página

Cada página, incluidas las del catálogo, tiene su texto en Markdown en su dirección seguida de `/llm.txt`: el mismo texto que copia "Copiar en Markdown", con cada enlace como dirección completa. Dos índices, siguiendo llmstxt.org, las listan:

| Dirección | Qué es |
| --- | --- |
| `/llms.txt` | Todos los repositorios, con cada página enlazada a su `llm.txt` y con su descripción |
| El slug del repositorio seguido de `/llms.txt` | Lo mismo, para un solo repositorio |

Las páginas se etiquetan con su grupo y sus secciones ("Escritura / Páginas / La cabecera"). Requieren las mismas credenciales que el lector: una sesión, o una clave de API en la cabecera `x-api-key`. `/llms.txt` es la excepción: sin credenciales responde con la guía para agentes (cómo conseguir la clave, conectar el MCP y «Configurar tu agente», el procedimiento que instala todas las skills), y con ellas añade los repositorios. Cada usuario crea sus claves en `/me`, donde obtiene el texto listo para pegar en su IA: «Skills para tu IA», o la pestaña «Skills» al crear una clave, con la clave ya puesta.

## Skills servidas

`skills/<name>/SKILL.md` son skills que la plataforma sirve a otros agentes, para que sepan cómo trabajar con este sitio desde cualquier proyecto. Siguen el formato Agent Skills: front matter con `name` y `description`, y las instrucciones debajo.

- **Delgadas:** dicen cómo trabajar y dónde mirar, nunca qué hay. Una skill descargada es una instantánea que se queda obsoleta; la documentación se lee en vivo.
- **Apuntan a páginas** en lugar de copiar procedimientos.
- **Solo lo específico del sitio:** lo que comparten todos los sitios, lo explican las skills de la propia plataforma (`colofon`, cómo usar el sitio, y las `colofon-*` de escritura, cómo escribir un repositorio de contenido).
- **Ningún secreto,** y tampoco pedírselo a una persona.

### Cómo se escriben

| Regla | Qué pasa si no se cumple |
| --- | --- |
| Una carpeta por skill, con un único `SKILL.md`; el nombre de la carpeta son minúsculas, cifras y guiones sueltos | La skill no se sirve y su problema sale en la portada |
| `name` es el nombre de la carpeta | Igual |
| `description` dice cuándo usarla, en 1024 caracteres como mucho | Igual |
| Los demás ficheros de la carpeta | Se ignoran |

Las demás skills del repositorio se siguen sirviendo aunque una falle.

### Cómo llegan a los agentes

La plataforma publica cada skill como el slug del repositorio seguido de su nombre: la skill `guide` de este repositorio, con el slug `doc-example`, es `doc-example-guide`, y el `name` de su front matter cambia a ese nombre al servirla. Así dos proyectos pueden tener cada uno su `deploy`.

| Dirección | Qué es |
| --- | --- |
| `/.well-known/agent-skills/index.json` | El índice de las skills que ve quien lo pide, en el formato Agent Skills discovery: nombre, descripción, dirección y digest SHA-256 de cada una |
| `/.well-known/agent-skills/<nombre>/SKILL.md` | Una skill |

Sin credenciales, el índice solo lista las skills de la plataforma; con una clave de API, también las de cada repositorio que el usuario puede leer. Una skill de un solo fichero sale con `type: "skill-md"` y la dirección de su `SKILL.md`. Una de la plataforma con más ficheros (sus `references/`) sale con `type: "archive"` y la dirección de un `.tar.gz` (`/.well-known/agent-skills/<nombre>.tar.gz`), con el `SKILL.md` en la raíz; cada uno de sus ficheros se lee también suelto, en `/.well-known/agent-skills/<nombre>/<ruta>`. El digest cubre los bytes exactos de lo que se descarga. «Configurar tu agente», en `/llms.txt`, explica a un agente cómo instalarlas todas, y el MCP las ofrece con `skills` y `skill` (que lee también un fichero de la skill).

Este sitio sirve `guide`: consulta `skills/guide/SKILL.md`. Las skills de escritura las sirve la plataforma a todos los agentes: [Agentes que escriben](writing-agents.mdx).
