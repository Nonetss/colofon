## Los ficheros

<Entities type="files" group="kind" columns="path,required,purpose" />

- Las **declaraciones** se leen primero: dicen qué puede contener el resto. Cuando una está rota, la plataforma sigue sirviendo la última versión válida de todas ellas, de modo que un error tipográfico nunca tumba el sitio.
- El **contenido** se lee junto con las páginas. Una página, entidad o diagrama rotos se reportan y el resto se publica igualmente.

```
doc.config.yaml          # el sitio
menu.yaml                # la barra lateral (opcional)
docs/
├── index.mdx            # la página de inicio
├── getting-started.mdx  # una página
└── network/             # una sección
    ├── index.mdx        # su página de entrada
    └── dns.mdx          # una de sus páginas
catalogo/
└── machines/            # un tipo: el nombre de la carpeta es su id
    ├── _tipo.yaml       # su declaración
    └── nas.yaml         # una entidad: el nombre del fichero es su id
diagramas/
└── network.json         # un diagrama: el nombre del fichero es su id
skills/
└── homelab/SKILL.md     # una skill servida a otros agentes
```

## Nombres del contrato y nombres tuyos

La plataforma lee un conjunto fijo de nombres, y están en español salvo las claves de los diagramas, que son las de los esquemas de la documentación anterior. Deben escribirse exactamente así, o el contenido deja de validar:

| Dónde | Nombres del contrato |
| --- | --- |
| Ficheros y carpetas | `doc.config.yaml`, `menu.yaml`, `docs/`, `index.mdx`, `catalogo/`, `_tipo.yaml`, `diagramas/`, `skills/` |
| `doc.config.yaml` | `nombre`, `descripcion`, `plataforma`, `cabecera` |
| `menu.yaml` | `secciones`, `titulo`, `icono`, `descripcion`, `paginas`, `ruta` |
| `_tipo.yaml` | `nombre`, `plural`, `icono`, `descripcion`, `etiqueta`, `campos`, `vista`, `columnas` |
| Un campo | `tipo`, `opcional`, `descripcion`, `valores`, `a`, `de`, `campos` |
| Cada cabecera de página | `titulo`, `descripcion`, `icono`, `orden`, `actualizado` |
| Cada entidad | `fuente`, `actualizado` |
| Un diagrama (JSON) | `type`, `variant`, `title`, `desc` y las de su forma: `width`, `height`, `nodes`, `edges`, `zones`, `notes` si se dibuja a mano, `items` y `links` en una cadena, las de su tipo si lleva `type` (ver [Diagramas](../diagrams/index.mdx)) |
| Enlaces | `catalogo:` seguido de un tipo, o de un tipo y un id |

Todo lo demás es tuyo, en el idioma que escribas: ids de tipo, nombres de campo, valores de enum, los campos de cabecera que declares, carpetas, nombres de fichero y cada palabra de las páginas. La plataforma no sabe nada de tu dominio: un homelab declara máquinas y servicios, una tienda declararía productos y proveedores.

## Nombres y rutas

- Los ficheros y carpetas van en minúsculas, con dígitos y guiones: `new-stack.mdx`, `docker-01.yaml`. Se convierten en URL e ids.
- Los nombres de campo van en minúsculas, con dígitos y guiones bajos, y empiezan por una letra: `public_ip`.
- `docs/catalogo/` está reservada: la plataforma genera ahí las páginas del catálogo, así que una página bajo esa ruta se reporta y no se publica.
