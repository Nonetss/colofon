## Un fichero por diagrama

Cada diagrama es un fichero propio, `diagramas/<id>.json`, así que se escribe una vez y se muestra donde ayude:

```mdx
<Diagram id="pipeline" />
```

Este es el de la portada de este sitio:

<Diagram id="pipeline" />

El contenido coloca cada caja, cada flecha y cada zona: la plataforma no mueve nada, solo lo dibuja con el aspecto de la plataforma (cajas con etiqueta, una pieza central, zonas de color, flechas en ángulo recto con su etiqueta y una leyenda debajo) y en claro u oscuro según el lector. Al pasar el ratón por una caja, una flecha o el título de una zona se ilumina lo que toca y una tarjeta cuenta qué es y con qué se conecta; en el móvil, el primer toque lo muestra y el segundo sigue el enlace.

## El fichero

```json
{
  "title": "Cómo despliega Komodo",
  "desc": "Komodo le dice a Periphery, en cada servidor, que levante los stacks",
  "width": 640,
  "height": 200,
  "zones": [
    { "id": "home", "x": 16, "y": 16, "w": 420, "h": 120, "label": "CASA", "hue": "teal" }
  ],
  "nodes": [
    { "id": "komodo", "entity": "services/komodo", "kind": "focal", "tag": "Núcleo",
      "x": 24, "y": 40, "w": 160, "h": 72, "zone": "home" },
    { "id": "periphery", "name": "Periphery", "sub": "agente en cada servidor",
      "x": 264, "y": 40, "w": 160, "h": 72, "zone": "home", "needs": ["komodo"] },
    { "id": "stacks", "name": "Stacks", "kind": "store", "shape": "cylinder",
      "x": 480, "y": 40, "w": 140, "h": 72 }
  ],
  "edges": [
    { "from": "komodo", "to": "periphery", "kind": "accent",
      "points": [[184, 76], [264, 76]], "label": "DEPLOY", "at": [224, 66] },
    { "from": "periphery", "to": "stacks",
      "points": [[424, 76], [480, 76]] }
  ]
}
```

Las coordenadas son píxeles del dibujo, desde su esquina de arriba a la izquierda. Las claves son las de los esquemas de la documentación anterior, en inglés, para poder traer uno casi copiando.

| Clave | Qué es |
| --- | --- |
| `title` | Obligatoria. Su título. |
| `desc` | Obligatoria. Qué muestra, en una o dos frases: es su texto alternativo y lo que leen los agentes. |
| `width`, `height` | Obligatorias. El tamaño del dibujo; la leyenda va debajo. |
| `nodes` | Obligatoria. Las cajas. |
| `edges` | Opcional. Las flechas y las insignias. |
| `zones` | Opcional. Rectángulos con título que agrupan cajas. |
| `notes` | Opcional. Texto suelto: `{ "x", "y", "text", "anchor" }`. |
| `kindNames`, `edgeNames`, `badgeName` | Opcional. Cómo llama la leyenda a cada tipo de caja, de flecha y a las insignias en este diagrama. |
| `shapes` | Opcional. La forma de todas las cajas de un tipo: `{ "store": "cylinder" }`. |
| `colorEdges` | Opcional. `true`: cada flecha toma el color de la caja de la que sale. |

### Cajas

Cada caja lleva `x`, `y`, `w` y `h`, y además lo que necesite:

- `id`: lo que nombran las flechas, las zonas y `needs`. En minúsculas, con dígitos y guiones.
- `kind`: `focal` (la pieza central), `service` (por defecto), `store` (datos o destino), `input` (usuario u origen), `external` u `optional` (sin uso, a trazos).
- `tag` (la etiqueta enmarcada arriba), `name`, `sub` (una línea o una lista bajo el nombre) y `shape` (`pill` para de dónde llega la gente, `cylinder` para dónde acaban los datos).
- `hue`: `rose`, `blue`, `cyan`, `violet`, `green`, `indigo`, `fuchsia`, `slate`, `teal` o `lime`. Sin él, la caja toma el de su zona.
- `zone`: el `id` de la zona en la que está.
- `info`: lo que dice la tarjeta al pasar por encima.
- `trace`: `true` en un origen ilumina todo lo que alcanza por el camino principal (las flechas `accent`).
- `needs`: los ids de las cajas de las que depende. Al pasar por una caja, la tarjeta lista todo lo que cae con ella.
- **`entity`**, una entidad del catálogo (`"services/komodo"`): toma su nombre si no lleva `name` y enlaza a su página, y la página de la entidad lista el diagrama. Úsala siempre que la caja exista en el catálogo. O **`page`**, la ruta de una página de este sitio a la que enlaza.

Una **tabla** no lleva `h`: lleva `rows`, una lista de columnas `{ "key": "PK", "name": "id", "type": "text" }`, y si quieres `more` ("+ 8 columnas más"); su alto sale de sus filas.

### Flechas

Cada flecha lleva sus `points`, en tramos solo horizontales o verticales (las esquinas se redondean solas), y además:

- `from` y `to` (ids de caja), o `toZone` cuando llega a una zona entera.
- `kind`: `default`, `accent` para el camino principal o `dash` para lo opcional o un aviso.
- `label` con `at`, el punto de la línea base de la etiqueta, y `anchor` (`middle`, `start` o `end`). La etiqueta dice **qué viaja** por ella, en pocas palabras y en mayúsculas; el detalle va en `info`.
- `hue`, `info` y `noHead` (`true`: sin punta).

Una flecha con **`badge`** no tiene línea ni `points`: es una insignia con ese texto en la caja `from`, del color de la caja `to`. Sirve para una conexión con una pieza lejana sin cruzar todo el dibujo con una línea.

### Cadenas

Para una fila de cajas unidas de izquierda a derecha no hacen falta coordenadas:

```json
{
  "title": "Copias",
  "desc": "De la máquina al PBS y de ahí a la nube",
  "items": [
    { "id": "vm", "name": "VM" },
    { "id": "pbs", "name": "PBS", "kind": "store" },
    { "id": "cloud", "name": "Nube", "kind": "external" }
  ],
  "links": ["SNAPSHOT", null],
  "accent": [0]
}
```

`items` son cajas sin `x` ni `y`, cada una tan ancha como su línea más larga (o su `w`); `links`, la etiqueta de cada flecha o `null`; `accent` y `dash`, qué flechas son de ese tipo (0 es la primera); `y` y `h`, la altura de la fila (40 y 72 por defecto).

## Qué se reporta

La plataforma valida cada diagrama contra el catálogo y las páginas. Se reportan, en el fichero con la ruta del campo (`nodes.3.entity`) **y** en cada página que lo muestra: el JSON mal escrito (con su línea y columna), una clave desconocida, una entidad o una página que no existe, una flecha a una caja que no está, un tramo en diagonal, una etiqueta sin `at`, un id repetido, una caja en una zona que no existe y un texto que no cabe en su caja. Lo que sea válido se sigue dibujando. Un `Diagram` con un id desconocido muestra un aviso, un `diagramas/<id>.yaml` se reporta (los diagramas son JSON) y un bloque de código con el lenguaje `diagram` dentro de una página también: los diagramas viven en `diagramas/`.

## En el editor

El editor de JSON de VS Code completa y valida los diagramas con el esquema que sirve la plataforma, con las entidades y páginas a las que puede enlazar una caja. Basta asociarlo en `.vscode/settings.json`, junto al ajuste de los YAML:

```json
{
  "json.schemas": [
    {
      "fileMatch": ["/diagramas/*.json"],
      "url": "https://<sitio>/api/v1/content/schemas/<slug>/diagram"
    }
  ]
}
```

## Para quien no lo ve

Para los lectores de pantalla y en el Markdown que reciben los agentes, el diagrama es texto: su título y su descripción, sus zonas con sus cajas y una línea por conexión ("Autor → Repositorio de contenido: GIT PUSH"), con cada entidad enlazada a su página.

## Pautas

- **Un diagrama, una idea.** A partir de una docena de cajas, divídelo.
- **Solo las conexiones que importan** para entender la página; el resto va en el texto.
- **Coloca en una rejilla de 4 px** y deja las etiquetas sobre tramos donde quepan.
- **Nada sensible** en etiquetas, subtítulos ni `info`.
