colofon es una plataforma para documentar sistemas que sirve a la vez a **personas** y a **agentes de IA**. La documentación vive en repositorios de contenido aparte (páginas en MDX, datos en YAML y diagramas en JSON); la plataforma los clona, los valida, los muestra en su lector y se los da a los agentes por `llms.txt`, por su MCP y como skills, sin que la IA vea nunca un secreto.

Por dentro es un monorepo de TypeScript sobre Bun, coordinado con Turborepo: un frontend Astro y un backend Hono con oRPC detrás de un gateway Caddy, sobre PostgreSQL. Nace de la plantilla `stack` y conserva sus paquetes (`@nonete/*`), sus convenciones y su sistema visual, de modo que el código se puede mover entre los dos repositorios sin reescribirlo. Lo que trajo la plantilla (autenticación, panel de administración, API tipada, planificador de crons, comentarios, iconos de entidad, Docker) sigue aquí; el producto encima es `packages/content` y todo lo que lo rodea.

## Qué hay en esta documentación

Estas páginas explican cómo funciona el proyecto y cómo se trabaja con él, con el porqué de cada pieza. El `README.md` de la raíz es el resumen rápido, en inglés, y `VISION.md` cuenta para qué existe el proyecto y qué viene después. Las reglas para los agentes de código están en `AGENTS.md` y en la skill `stack` (`.agents/skills/stack/`); aquí se cuenta lo mismo con más contexto. Si alguna vez no coinciden, mandan las specs de `openspec/specs/` y el código.

Cómo se **escribe** un repositorio de contenido no está aquí: lo explica la guía «Escribir documentación», el sitio de `doc-example/`. Esta documentación cuenta lo que la plataforma hace con él.

| Término | Qué es |
| --- | --- |
| **Repositorio de contenido** | Un repositorio git con la documentación de un sistema: `doc.config.yaml`, `menu.yaml`, `docs/`, `catalog/`, `diagrams/`, `styles/` y `skills/`. |
| **Workspace** | Cada carpeta de `apps/*` y `packages/*` con su propio `package.json`. Bun las enlaza entre sí. |
| **Procedimiento** | Una operación de la API (por ejemplo `cron.list`). Se define una vez y se puede llamar por RPC o por HTTP. |
| **Feature (API)** | Un grupo de procedimientos relacionados, en su carpeta `packages/api/src/v1/<feature>/`. |
| **Feature (frontend)** | Un dominio de la interfaz (`docs`, `admin`…), en `apps/frontend/src/features/<dominio>/`. |
| **Slice** | Un caso de uso dentro de un dominio del frontend (`overview`, `detail`…). |
| **Superficie** | Cualquier página con identidad propia (título, etiqueta, icono), declarada en `app-surfaces.ts`. |
| **Isla** | Un componente React montado dentro de una página Astro. |
| **Capability (OpenSpec)** | Un área funcional con sus requisitos en `openspec/specs/<capability>/spec.md`. |

## Cómo se mantiene esta documentación

Esta carpeta es un repositorio de contenido de colofon, registrado con la carpeta del contenido `docs`: `doc.config.yaml`, `menu.yaml`, las páginas en `docs/`, los datos en `catalog/` y los diagramas en `diagrams/`. Los diagramas son JSON que la plataforma dibuja con el sistema visual del frontend, así que se editan como datos y no se exportan. Los `.svg` de `img/` son los diagramas del `README.md` de la raíz; la plataforma no los lee. Las convenciones del sitio están en `AGENTS.md`, sección «Documentation site (`docs/`)».
