La plataforma da a los agentes tres puertas, y las tres respetan lo que el
usuario puede leer en el lector: nunca enseñan un repositorio o una página que
ese usuario no vería.

| Puerta | Para qué | Dónde |
| --- | --- | --- |
| Markdown por página | Leer una página sin HTML | `/<slug>/<ruta>/llm.txt` |
| Índices | Encontrar las páginas | `/llms.txt` y `/<slug>/llms.txt` |
| MCP | Buscar, leer y consultar el catálogo con herramientas | `/mcp` |
| Skills | Instalar en el agente cómo trabajar con el sitio | `/.well-known/agent-skills/` |

## Credencial

Un agente se autentica con una **API key** en la cabecera `x-api-key`. Cada
usuario crea las suyas en `/me/api-keys` y, al crearla, la pantalla le da las
instrucciones listas para pegarle a su IA. La key lee con los permisos de su
dueño. Las API keys se crean sin límite de peticiones; las creadas antes de
ese cambio conservan el límite del plugin (10 al día, y cada `llm.txt` gasta
dos), así que la que use un agente hay que volver a crearla.

| Ruta | Sin credencial |
| --- | --- |
| `/llms.txt`, el índice de skills y las skills de la plataforma | Responden, mostrando solo lo que no necesita clave |
| `llm.txt` de una página y `/<slug>/llms.txt` | `401` con una línea que explica cómo enviar la key, en lugar de mandar al login |
| `/mcp` | `401` con la misma explicación |

El MCP rechaza con `403` una petición cuyo `Origin` no sea el origen público.
Las direcciones completas de los textos salen de `CORS_ORIGIN`.

## `llm.txt` y los índices

Cada página se lee en Markdown añadiendo `/llm.txt` a su dirección
(`/<slug>/red/dns/llm.txt`, o `/<slug>/llm.txt` para la portada). Es el mismo
texto que copia «Copiar en Markdown», con los enlaces como direcciones
completas. Los índices siguen [llmstxt.org](https://llmstxt.org): `/llms.txt`
lista todos los repositorios que el usuario puede leer, uno por sección, y
`/<slug>/llms.txt` uno solo, cada página enlazada a su `llm.txt` con su
descripción.

## El MCP

`/mcp` es un servidor MCP sin estado (Streamable HTTP; un `GET` o `DELETE`
responde `405`) que solo declara herramientas de lectura:

| Herramienta | Qué hace |
| --- | --- |
| `repositories` | Lista los repositorios que el usuario puede leer. |
| `index` | El índice `llms.txt`, global o de un repositorio. |
| `search` | Busca en las páginas, con las mismas reglas que el navbar. |
| `read` | Lee una página en Markdown, o solo una sección si la ruta lleva `#sección`. |
| `entity` | Lee la ficha de una entidad del catálogo por su tipo y su id. |
| `skills` y `skill` | Lista las skills visibles y lee una o uno de sus ficheros. |
| `sync` | Solo administradores: sincroniza un repositorio tras un push. |
| `secrets` y `request` | Solo con los secretos activados (ver abajo). |

## Skills

La plataforma sirve skills en el formato Agent Skills, por el descubrimiento
`/.well-known/agent-skills/` (el índice, cada skill y su archivo `.tar.gz`):

- **Las de la plataforma** (`colofon` y las `colofon-*`) son las mismas en
  todos los sitios: cómo trabajar con la plataforma y cómo escribir un
  repositorio de contenido. Salen de `packages/api/skills/` y de
  `doc-example/.agents/skills/`. Se sirven sin credencial.
- **Las de cada repositorio** son las de su carpeta `skills/`, y solo las ve
  quien puede leer ese repositorio. Una skill con un nombre repetido entre
  repositorios se distingue por el repositorio.

En `/me/skills`, la sección «Skills para tu IA» muestra un texto para pegar en la IA:
con él se configura sola e instala las skills que el usuario ve. Sin una key
solo instala las de la plataforma.

Una skill rota (sin `SKILL.md`, con un `name` distinto de su carpeta o sin
`description`) se deja fuera y se avisa; el resto del repositorio se lee igual.

## Secretos

Un usuario guarda en `/me/secrets` las credenciales de los servicios que la
documentación describe, y la herramienta `request` del MCP llama a esos
servicios con ellas **sin que el agente vea nunca un valor**.

- Los valores se cifran en la base de datos (AES-256-GCM) y no se vuelven a
  mostrar una vez guardados.
- El agente escribe la petición con marcadores, como `{{nombre.campo}}`, y la
  plataforma los rellena y envía ella misma. La respuesta se devuelve con los
  valores enmascarados.
- Cada secreto declara los orígenes a los que puede enviarse y si se permite
  usarlo en escrituras, en la URL o en el cuerpo. Antes de enviar se comprueba
  todo, y una petición sin marcadores se rechaza: no es un proxy general.
- La herramienta `secrets` lista los secretos (nombre, campos, orígenes y
  permisos, nunca valores) y se registra cada uso.

La función está **apagada mientras no exista `SECRETS_ENCRYPTION_KEY`** (ver
[Configuración](../configuracion.mdx)). Perder o cambiar esa clave deja ilegibles
todos los secretos guardados, y hay que volver a escribirlos.
