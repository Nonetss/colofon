1. **Busca si ya existe.** `rg -n "summary:" packages/api/src/v1` da un
   índice rápido de todos los procedimientos. Si hay uno parecido,
   extiéndelo (un filtro opcional, un campo más en la salida) en vez de crear
   un hermano, salvo que el método o el acceso cambien.
2. **Elige la feature** cuyos datos lee o escribe. Si es un área nueva, crea
   la carpeta `src/v1/<feature>/` y móntala en `src/v1/router.ts`.
3. **Define la entrada y la salida** en `input.ts` y `output.ts`, agrupadas
   por método.
4. **Escribe la lógica** en `handler.ts`, en un método que recibe un único
   objeto con `context` e `input`. Reutiliza los
   [helpers compartidos](helpers.mdx).
5. **Cabléalo** en `router.ts`: el [builder](builders.mdx),
   `.meta(openapi(...))` con un `summary` y una `description` en inglés, el
   [método y el estado](metodos-http.mdx) correctos, `.input()` una sola
   vez, `.output()` y `.handler()`.
6. **Escribe sus tests** en
   `packages/api/tests/v1/<feature>/handler.test.ts`, un
   `describe("<feature>.<método>")` por método: el caso feliz, cada código de
   error que lanza (sin escribir nada) y las filas que escribe.
7. **Úsalo desde el frontend** con `orpc.v1.<feature>.<método>`, a través de
   TanStack Query.
8. **Valida** con `bun run check-types`, `bun run check` y `bun run test`
   (ver [Desarrollo](../desarrollo/index.mdx)).

## Si tiene que verlo un agente

- Una API key llega a todo procedimiento que no sea `sessionProcedure`, con
  los permisos de su dueño. Si un agente no debe poder hacerlo, usa
  `sessionProcedure` ([API keys](../autenticacion/api-keys.mdx)).
- Si lee contenido para alguien, pasa siempre el público de quien llama al
  lector (`v1/content/reader.ts`), para que un repositorio privado no se
  filtre.
- Una herramienta nueva del MCP llama a procedimientos, nunca a handlers ni
  a la base de datos: así ve exactamente lo que el lector enseña a ese
  usuario (ver [Agentes de IA](../contenido/agentes.mdx)).

## Si falla

| Síntoma | Causa | Qué hacer |
| --- | --- | --- |
| El frontend no ve el procedimiento nuevo en `orpc.v1` | La feature no está montada en `src/v1/router.ts` | Añade su clave al router de la versión |
| La entrada o la salida tienen campos de más | `.input()` o `.output()` se llamaron dos veces: en v2 se acumulan | Llámalos una sola vez |
| Una llamada responde 413 | El cuerpo pasa de 1 MiB, el límite de todos los manejadores | Reduce la entrada; subir el límite es un cambio en `apps/backend/src/routers/handler-plugins.ts` |
| Una llamada por `/rpc` responde 404 | Se envía como `QUERY` (marcada como lectura) y el procedimiento no está declarado `GET` ni `QUERY` | Declara el método correcto o quita la marca de lectura |
