El gateway firma `https://localhost:4321` con la autoridad de certificación local de Caddy (`tls internal`), guardada en un volumen para que no cambie entre reinicios.

1. Arranca el gateway al menos una vez ([con Docker](docker.mdx) o [en nativo](nativo.mdx)).
2. Exporta la raíz:

   ```bash
   bun run dev:cert   # deja caddy-local-root.crt (ignorado por git) en la raíz
   ```

3. Impórtala en el navegador como autoridad de confianza:
   - **Chrome**: `chrome://certificate-manager`, certificados personalizados.
   - **Firefox**: Ajustes → Privacidad y seguridad → Certificados → Ver certificados → Autoridades → Importar, marcando que identifique sitios web.
4. Recarga la página.

Si borras el volumen (`bun run dev:down -v`) se crea una autoridad nueva y hay que importarla otra vez.

## Una autoridad por modo

`bun run dev:cert` exporta la autoridad del volumen `colofon-dev_gateway_data`, la del gateway de `compose.dev.yml` (`bun run dev`). El gateway nativo (`bun run gateway`) pertenece a otro proyecto de Compose, `stack-dev`, y guarda la suya en `stack-dev_gateway_data`: es otra autoridad. Si trabajas en nativo, exporta esa:

```bash
docker run --rm -v stack-dev_gateway_data:/data:ro caddy:2-alpine cat /data/caddy/pki/authorities/local/root.crt > caddy-local-root.crt
```

Si usas los dos modos, importa las dos autoridades.

## Por qué HTTPS en local

Los navegadores solo usan HTTP/2 sobre TLS. Con HTTP/2, los cientos de módulos sin empaquetar que sirve Vite en desarrollo comparten una conexión en vez de hacer cola en seis. `astro dev` no puede hacerlo solo, porque Vite pierde HTTP/2 cuando usa su proxy; por eso lo hace el gateway delante.

Un `http://localhost:4321` sin cifrar recibe una redirección a `https` en el mismo puerto. El gateway de desarrollo no abre el puerto 80.

## Si algo falla

| Síntoma | Causa | Qué hacer |
| --- | --- | --- |
| El navegador avisa de que `https://localhost:4321` no es seguro | No has importado la autoridad, o borraste el volumen y se creó otra | Exporta e importa la raíz otra vez |
| `dev:cert` falla con `No such file or directory` y deja un `caddy-local-root.crt` vacío | El gateway de ese volumen no ha arrancado nunca (o trabajas en nativo, cuyo volumen es otro) | Arranca el gateway una vez, o usa el comando de [Una autoridad por modo](#una-autoridad-por-modo) |
| El aviso sigue tras importar | Importaste la autoridad del otro modo | Importa la del modo que estás usando |
